# Extended public research catalogue

Private deployment only; enable with ASK_RESEARCH_EXTENDED=true on both API and worker after provisioning. Core-only defaults remain unchanged. This extends version-three SELECT research, not the version-two plan schema.

The same reviewed native source publication carries pool daily snapshots, successful-swap source columns, transparent address summaries and address incidences. Apply catalogue-destination-v1.sql on the dedicated analytics database first; update its trusted admission script; then apply catalogue-source-v1.sql on the existing mainnet publisher and refresh the existing subscription with copy_data=true. These source grants/publication edits are real production metadata changes, not a read-only source inspection. No API/indexer/schema row mutation or restart is required on the source. Use one destination initial-copy worker at a time, retain finite WAL/disk guard and monitor replay, source health and copy progress. Address activity is a large history, not an instant feature. Never copy source/provider credentials into the query worker.

Published names: blocks, transactions, flows, daily, swaps, addresses, address_activity, activity_daily and flow_daily, plus address_daily once address-daily-v1.sql is applied (see address-daily.md), supply_daily/issuance once supply-issuance-v1.sql and its source step are applied (see supply-issuance.md), mining_daily/software_daily/block_timing/issuance_daily once mining-v1.sql and its source step are applied (see mining.md), and reorgs/orphaned_blocks once reorgs-v1.sql and its source step are applied (see reorgs.md). A dataset stays published:false in lib/ask/research-catalogue.js, hidden from the catalogue, guidance and SQL admission, until its host rollout is verified. Each added view is independently gated by dataset_coverage plus canonical core admission. The trusted admission process checks native table copy readiness and applied source checkpoint. Warm/stale copies fail before execution and cache lookup; they cannot masquerade as empty history. The worker continues to deny raw/metadata tables, mutation, file/network/session functions and role escalation. Added raw tables belong to the NOLOGIN operator owner; only reviewed views are readable. Native address publication filters t1/t3 prefixes using replica-identity address columns. The current summary view further requires transparent address_type. Address incidences include coinbase and validate canonical transaction/hash/height/time, but no independent historical-address completeness certification is claimed.

Daily activity and flow summaries are local derived data over completed UTC days. The trusted refresh-ask-summaries.js process aggregates each grain before joining; missing fees/bytes remain null and have counts. Dirty-day revision tracking handles historical corrections and changes in old/new timestamps; racing corrections abort/retry or retain a dirty revision. A pending completed day hides the summaries until corrected. Source truncation invalidates admission/derived readiness. Install the summaries service/timer on the analytics host. Initial refresh defaults to 100-day batches (operator maximum 500), derives indexed height bounds before aggregating, and uses a 60-second statement timeout for the trusted operator; user quick/queued timeouts stay 3/30 seconds and temp remains 16MiB. Queue, cancellation and daily/cost ceilings are unchanged. Aggregates accelerate long ranges; they do not promise arbitrary heavy joins will finish.

Source meanings: daily consists of maintained privacy_trends_daily observations, with non-coinbase activity and closing pool stocks in zatoshis, never summable stock volume. swaps consists of successful cross_chain_swaps dated by provider creation time, counterparty USD (source for inflow, destination for outflow), legacy zero -> null, excluding ZEC-to-ZEC. It is not every swap or exchange. addresses contains current maintained balances, not past balances or users; address_activity is one address/transaction incidence, not a unique user/transaction count. flow_daily aggregates recorded public boundaries, not private transfers and not certified complete flow history. All amounts/fees are exact zatoshis unless explicitly converted; one ZEC=100000000 zatoshis. Daily dates are UTC; swaps uses timestamptz, other timestamps Unix seconds.

Anonymous-only improvement telemetry is owner-selected and separate from operational ephemeral SQL/result tickets. ASK_RESEARCH_METRICS_ENABLED=true counts fixed outcome, duration bucket, dataset, query-feature, time-span and quick/queued categories in a day key, plus joint counts of those fixed tokens in a capped shape key, both with 30-day expiry (address-daily.md). No questions, SQL, SQL fingerprints, addresses, IPs, user IDs, arbitrary aliases or raw exceptions enter these counters. It covers quick and queued worker research executions, not every guided/knowledge response or all pre-execution denials. Metrics failures cannot change query outcome/admission. Operator CLI read-ask-research-metrics.js reads fixed UTC-day keys (one day or --days N up to 30, with --heavy ranking) and validates all categories. No public metrics endpoint. Existing query tickets expire in one hour and result cache in 30 seconds; these remain execution state, not training history. Explicit browser saves stay local.

This does not automatically retrain the model. ask-research-benchmarks.js holds reviewed example questions/SQL for deterministic policy checks and independent numerical/runtime checks; live model planning needs separate repeated evaluation. Usage counters can guide which cases to add. Do not promote arbitrary successful user SQL to trusted examples or weaken security from feedback. Public sharing/ratings/MCP/BYOK remain separate product work.

Repeatable operator runtime check: run `server/api/scripts/benchmark-ask-research.js` with the private loopback forward and existing worker service key in the environment. Optional arguments select only reviewed case IDs; omitted arguments run all eight fixed cases. Output contains case IDs, outcomes, row counts and end-to-end times, not SQL/result rows. It uses normal queue, reader and quota gates. Timings include polling/transport and are not SQL execution times or load-test percentiles. A successful execution is not proof of model interpretation or numerical correctness; compare selected totals independently and retain reviewed numerical fixtures separately. Never use visitor content as a benchmark fixture without separate authorization.
